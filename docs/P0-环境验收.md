# P0 环境验收

开发机为 macOS Apple Silicon。Python 集成环境使用 CPython 3.12.13 和 uv 0.12.5，原有 SQLite 套件另用 CPython 3.14.5 验证。第三方组件的安装组合以本次实测平台与解释器为准。

## 重跑方式

在项目根目录运行。数据库检查需要可用的本机 Docker Engine 和 Docker Compose，首次需要拉取锁定镜像。Python 依赖通过 PyPI 的带哈希锁文件安装到项目虚拟环境。

```bash
uv lock --check
uv sync --locked --all-extras --python 3.12 --no-build
uv pip check --python .venv/bin/python
uv run --locked --all-extras --python 3.12 deployment/local-postgres/verify_dependencies.py
uv run --locked --all-extras --python 3.12 deployment/local-postgres/verify.py
PYTHONDONTWRITEBYTECODE=1 PYTHONWARNINGS=always::ResourceWarning PYTHONTRACEMALLOC=5 \
  uv run --locked --all-extras --python 3.12 python -m unittest discover -s tests -v
```

只需验证数据库时，安装和运行命令可以用 `--extra postgres` 代替 `--all-extras`。原有 SQLite 演示和测试可以直接使用 Python 标准库运行。

数据库脚本使用独立 Compose 项目、临时密码、动态分配的回环端口和临时数据库。管理员启用扩展，迁移账号通过 Alembic 创建测试表，运行账号通过 Psycopg 连接池写入两条向量并回滚第三条。脚本核对已提交记录和向量距离排序，检查运行账号创建表、创建 schema 和修改表均被权限拒绝。退出时清理该项目的测试容器和卷。镜像由 digest 固定，脚本也核对服务端和扩展返回的版本。[Compose 配置](../deployment/local-postgres/compose.yaml) · [验证脚本](../deployment/local-postgres/verify.py)

## PostgreSQL 实测

在本机 Docker 镜像下载期间，用 PostgreSQL 18.7 的上游源码与校验文件、pgvector 0.8.7 的发布标签构建独立的 macOS arm64 临时实例。使用锁定环境运行仓库脚本的 `verify_database`，实际通过连接池、Alembic 建表、角色权限、提交、回滚和距离排序。运行账号的四条 DDL 尝试均被拒绝，临时数据库实例随后停止。[PostgreSQL 18.7 源码目录](https://ftp.postgresql.org/pub/source/v18.7/) · [pgvector v0.8.7](https://github.com/pgvector/pgvector/releases/tag/v0.8.7)

在 Docker Engine 29.5.2 和 Compose 5.1.4 上，两次从固定镜像创建独立数据库并完整运行 `verify.py`，分别使用数据库可选依赖和完整集成依赖。均实测返回 `PostgreSQL 18.7 (Debian 18.7-1.pgdg12+2), pgvector 0.8.7`，所有数据库检查通过。实测镜像为 Linux arm64，首次网络拉取慢时通过分段下载并校验镜像内容摘要完成加载。两次验证退出后均已清理验证项目的容器、网络和卷。

## Python 实测

| 检查 | 实际结果 |
| --- | --- |
| SQLite 原有测试，CPython 3.14.5 | 两次诊断复跑均为 59 项通过，最终一次 13.199 秒，连接告警和析构异常均为零 |
| SQLite 原有测试，CPython 3.12.13 完整集成环境 | 59 项通过，正常锁定安装后的复跑为 10.374 秒，连接告警和析构异常均为零 |
| 基础 Python 环境 | 从锁文件安装，不启用可选依赖，环境中安装的第三方包数量为零 |
| 完整 Python 环境 | `uv sync --locked --all-extras --python 3.12 --no-build` 安装 149 个包，离线缓存可重新构建，`uv pip check` 通过，12 个直接依赖的模块可在同一进程加载 |
| OWP 和 MCP SDK | 本地 stdio 协议协商为 `2026-07-28`，发现 32 个工具，调用只读工具获取 WorkOrder schema |
| LangGraph | 内存中的单节点图运行并返回预期值 |

OWP、LiteLLM、Langfuse 和模型侧验证使用本地导入或测试数据。P0 对 LangGraph 的 PG 检查点和 LlamaIndex PG 向量适配验收到了安装和导入，集成到真实框架流程分别在 P6 和 P7 验收。[依赖验证脚本](../deployment/local-postgres/verify_dependencies.py)

59 项原有测试包括 API 2 项、数据 5 项、模型路由和模型接口各 6 项、运行时 13 项、运行维护 6 项、远端运行时 14 项、远端传输 6 项及 MCP 运行时 1 项。上面的详细模式列出每个用例和结果。

## 后续验收边界

P1a 定义 Ontology、事实、连接器与动作契约。P1b 接入框架主库并验证正式版本迁移、旧数据导入、并发和恢复。P2a 验收租户权限，P3–P7 依次集成 OWP 授权、MCP 工具、模型、编排及知识检索。P0 数据库与第三方包的独立运行检查为这些阶段提供版本基线。
