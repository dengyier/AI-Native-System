# P5 模型接入、Embedding 与观测验收

## 已实现

- LiteLLM 1.109.1 通过显式配置的 OpenAI 兼容端点调用生成和 embedding。企业发布快照绑定具名路由、配置版本、端点、请求模型、系统提示指纹、数据策略、计价版本和单跳回退。供应商响应的模型身份单独记录。凭据从进程环境读取，可轮换。
- 发送前重查当前任务租约、发布、事实和权限。请求者与执行服务都须具备目标模型路由的 `use / model / 路由名` 权限。回退仅针对标记为可恢复的供应商失败，并重新通过同样的审查。模型可见范围使用属性、关系和知识白名单，历史交接可显式投影为上阶段动作名。
- PostgreSQL 在每次物理尝试前按租户预留 Token 与金额并限制并发。回退共享同一个逻辑调用的次数和总截止。模型返回的用量即使晚于任务取消也会结算，业务结果仍由 Runtime 核对租约和事实后处理。未报告的用量单独显示，并按对应预留值占用预算。
- Embedding 独立配置供应商、数据范围、模型、版本、维度与价格。文档和查询使用同一路由时，以 `provider / model / version / preprocessing_version / dimensions` 作为对接 P7 的向量空间身份。P5 传输原文，配置的预处理版本用于标识调用方约定。
- Langfuse 5.2.0 的观测字段通过 OTLP 导出。调用结算与脱敏观测队列同事务持久化，独立 worker 有界重试。用量记录的 `task_id` 可与 Runtime 审计和 OpenWorkProof 证据关联，`trace_id` 可定位同一调用的各次模型尝试。导出字段限定为散列后的引用、状态、耗时、Token 和金额。原始文档、提示、模型正文、向量、凭据和原始证据保存在各自原有边界内。

## 配置与运行

接入模型时复制 [P5 模型配置样例](../fixtures/models-p5.json)，填写经许可的端点、供应商、凭据环境变量和每 Token 的价格。`input_nanos` 与 `output_nanos` 使用十亿分之一美元。管理端、Runtime 和 embedding worker 使用一致的租户预算配置。升级前由迁移角色应用 `0014_model_accounting` 和 `0015_model_observability`。

| 角色 | P5 所需权限 |
| --- | --- |
| Runtime 与 embedding | 对 `model_calls` 和 `model_attempts` 授予 `SELECT, INSERT`。只允许更新尝试的 `outcome, input_tokens, output_tokens, actual_provider, actual_model, finished_at`。对 `model_trace_outbox` 授予 `SELECT, INSERT` |
| 用量查询 | 对 `model_calls` 和 `model_attempts` 授予 `SELECT`，由 `AI_NATIVE_P5_USAGE_DSN` 连接 |
| 观测 worker | 对 `model_trace_outbox` 授予 `SELECT`，只允许更新 `state, attempts, lease_token, lease_until, available_at, sent_at, last_error`，由 `AI_NATIVE_P5_OBSERVATION_DSN` 连接 |

这些权限应用于 `ai_native` schema，连接角色也需要读取 `schema_migrations`。企业 embedding 调用须获得 `embed / model / 路由名 / 数据范围` 权限。CLI 用于持有相应数据库连接权限的可信操作进程。批量调用方负责按真实权限读取文档并声明其发送范围。

```bash
python -m ai_native_system --postgres --tenant "$tenant" --models "$model_config" models
python -m ai_native_system --postgres --tenant "$tenant" --models "$model_config" \
  p5 embed document-vector input.txt --scope tenant --purpose document --actor "$actor"
python -m ai_native_system --postgres --tenant "$tenant" p5 usage --limit 50
python -m ai_native_system --postgres --tenant "$tenant" p5 flush-traces --limit 20
```

观测 worker 读取 `LANGFUSE_HOST`、`LANGFUSE_PUBLIC_KEY`、`LANGFUSE_SECRET_KEY`。队列有独立租约，发送失败会延后重试，达到上限时保留失败状态。每次 `flush-traces` 处理有限批次。

## 测试与适用范围

```bash
python -B deployment/local-postgres/verify_p5.py
python -B deployment/local-postgres/verify_migration.py
python -B deployment/local-postgres/verify_runtime.py
```

使用 Docker 中的 PostgreSQL 18.7 和受限角色。真实 LiteLLM SDK 向回环 HTTP 模型测试端发送请求，Langfuse SDK 的观测字段与真实 OTLP 请求发送至回环接收端。端到端覆盖回退与权限拒绝、数据裁剪、禁止动作、预算拒绝、取消后记账、不可变发布、embedding CLI、观测故障和 OpenWorkProof 审批执行证据。

| 验证方式 | 结果 |
| --- | --- |
| `verify_p5.py` | 28 项通过，含 8 项 PostgreSQL 端到端流程 |
| `verify_migration.py` 与 `verify_runtime.py` | 18 项 PostgreSQL 回归通过 |
| `verify_p3.py` 与 `verify_p4.py` | 37 项 OpenWorkProof 和 35 项 MCP、源写入及证据流程回归通过 |
| `python -B -m unittest discover -s tests` | 139 项通过。其余 143 项需要各自的专用数据库环境 |

- 成本按供应商返回的 Token 乘以配置费率计算。预算按同租户账本累计，当前无自动周期重置。输入预留以配置值为准，并独立限制请求字节数。供应商报告的实际用量超出预留时，账本记录差额并在后续准入中扣除。
- 单次生成或 embedding 有总截止时间。任务级持久调度、跨阶段截止和长运行续租由 P6 接续。工作进程退出或超时可能留下未知用量，供应商账单对账和真实端点验证列入上线验收。
- 本地验收覆盖 Langfuse 接收协议和重试。部署端的实际入库、告警与监控看板由部署环境验收，知识索引、授权向量检索和评测由 P7 完成。
