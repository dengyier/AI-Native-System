# P7 权限知识检索、记忆与评测验收

## 实现范围

- LlamaIndex 0.14.26 处理文本与 Markdown 分段。片段固定源 ID、文档版本、索引版本、字符和 UTF-8 字节位置以及内容 SHA-256。引用可定位到原文，重复文本及换行保留原始位置。
- 每个索引绑定 P5 embedding 路由、实际模型标识、端点配置摘要、模型版本、预处理版本、维度、分段器版本和余弦距离。同一空间可复用已存向量。分批入库可恢复，完整片段集合在同一事务发布。新空间先回填当前文档，再切换读流量。
- pgvector 查询将租户、文档权限、委派范围、当前版本和撤回状态纳入 SQL。精确检索按获准集合排序，HNSW 使用按租户和空间建的索引。过滤后候选不足时，回退到有界的获准集合精确检索。返回前再核对引用和当前权限。
- 企业应用发布通过 `authorized-fragments-v1` 显式选择片段。任务提交传入该发布允许的 `knowledge_citations`，引用随任务固定。重新规划、审批、OpenWorkProof 授权和执行前复核文档、引用和事实，现有发布继续使用固定文档引用。向量相似度用于检索，候选证据需要独立人工审核，已审核引用可交由现有事实服务处理。
- 任务和显式跨任务记忆按账号、服务和委派范围隔离。任务和跨任务记忆分别最长 24 小时和 7 天，可主动删除。记忆仅保存来源引用，读取时重新授权和解析。撤回文档或片段时，实时检查立即拒绝访问，P2b 失效消费者随后清理引用并保留处理回执。关联复核候选的记忆也随其事实变更失效。
- LlamaIndex 计算排名命中率和 MRR，确定性断言覆盖可见范围、引用有效性、对动作的引用支持、动作选择、重复效果、冲突、注入、时延和成本。报告固定完整发布和数据集摘要，人工评分单独记录。提供显式关联 Langfuse trace 的数值评分接口。

## 配置和运行

数据库管理员先在业务数据库安装 `vector` 扩展，再使用迁移角色运行 `migrate` 至 `0019_knowledge_tasks`。向量、文本、候选、记忆和评测记录可在同一个 PostgreSQL 数据库中，表权限和 RLS 划分读写职责。HNSW 使用独立 DDL 连接，建索引使用并发模式。P5 模型配置需要已获准的 tenant 级 embedding 路由。

| 操作 | 授权 |
| --- | --- |
| 录入、回填和继续入库 | `write / knowledge-index / 索引`，`read` 与 `write / document / 文档`，`embed / model / 路由 / tenant` |
| 切换索引 | `publish / knowledge-index / 索引`，并具备索引覆盖的当前版本 |
| 检索 | 实际索引版本的 `read / knowledge-index / 索引`、当前文档 `read` 及 embedding 路由授权 |
| 打开或复验原片段 | 原引用索引的 `read / knowledge-index / 索引`、当前文档 `read` 和有效委派，复核文档版本及撤回 |
| 撤回或删除 | `withdraw` 或 `delete / document / 文档` |
| 记忆 | 任务或明确 `memory_scope` 的 `read`、`remember` 或 `forget` 权限，以及实时文档 `read` |
| 候选证据和评测 | 目标相关的文档、发布和语义资源权限，单独的 `propose` 或 `review / evidence / 文档`，评测需要 `evaluate / release / 发布` |

`AI_NATIVE_KNOWLEDGE_DSN` 用于录入、候选、失效消费者和评测。依实际职责分别配置账号。写入角色需要知识空间、文档和片段的相应权限，发布与撤回同事务写入 P2b 失效记录。`AI_NATIVE_KNOWLEDGE_INDEX_DSN` 用于索引 DDL。搜索和记忆使用 `AI_NATIVE_POSTGRES_DSN`，搜索角色沿用 P5 模型账本所需权限。失效消费者应有候选失效字段更新、记忆删除、读取 P2b outbox 和写入处理回执的权限。

```bash
python -m ai_native_system --postgres migrate
python -m ai_native_system --postgres --tenant "$tenant" --models "$models" p7 create-index v1 document-vector --actor "$actor"
python -m ai_native_system --postgres --tenant "$tenant" --models "$models" p7 ingest v1 doc-a source-a document.md --format markdown --actor "$actor"
python -m ai_native_system --postgres --tenant "$tenant" p7 build-hnsw v1
python -m ai_native_system --postgres --tenant "$tenant" --models "$models" p7 activate-index v1 --actor "$actor"
python -m ai_native_system --postgres --tenant "$tenant" govern grant "$actor" read knowledge-index v1
python -m ai_native_system --postgres --tenant "$tenant" --models "$models" p7 search '检索词' --method hnsw --actor "$actor"
python -m ai_native_system --postgres --tenant "$tenant" p7 invalidate --limit 50
python -B deployment/local-postgres/verify_p7.py
```

新发布通过 `release draft --knowledge-strategy authorized-fragments-v1` 选择片段策略，再按现有流程绑定规则、发布及选择。策略切换是一次发布迁移。使用企业任务提交接口传入检索结果中的 `citation` 对象数组，条数限制为 1–10。

P9 统一按解析出的实际索引检查读取授权。默认活动索引、显式版本、精确、HNSW、中文混合检索、回退及评测均沿用该限制。已退役的原引用可在授权有效且当前文档可读时复验。撤销索引读取权限后，旧引用、记忆及证据候选不能继续提供相应正文，待执行动作按原引用复验。[P9 索引读取授权](P9-企业试点与恢复演练.md#索引读取授权) · [P9 中文混合检索](P9-企业试点与恢复演练.md#中文混合检索)

`p7 retire` 返回可保存在可信外部存储的撤回凭据。撤回从在线检索移除内容并可保留受控历史，删除同时清除已存正文、片段和向量。恢复旧备份时，应先重放保留的 P2b 失效事件及 `p7 reapply-tombstone`，再开放检索和新动作。已发生的业务效果及审计保留原记录。企业下游产物、外部备份和其他历史副本的保留与清除按 P9 部署政策验收。

## 测试边界

本地验证使用 PostgreSQL 18.7、pgvector 0.8.7、实际 LlamaIndex 分段与排名评测，以及真实 LiteLLM SDK 调用回环 embedding 端点。验证从片段引用到 OpenWorkProof 执行，覆盖权限撤销先于后台消费、版本与维度切换，以及读取或执行使用旧片段时的处理。

| 验证方式 | 结果 |
| --- | --- |
| `verify_p7.py` | 28 项通过，含 4 项完整链路，应用迁移为 `0019_knowledge_tasks` |
| `verify_migration.py` 与 `verify_p2a.py` | 7 项迁移回归和 22 项身份、权限、发布与任务回归通过 |
| `verify_p6.py` | 33 项编排、检查点和受保护流程回归通过 |
| `python -B -m unittest discover -s tests` | 157 项通过。其余 186 项在专用数据库或服务环境运行 |

索引对照使用 1,608 条二维合成向量，其中 68 条已获准。该次运行确认查询计划走 HNSW，Recall@12 为 100%，精确查询 14.039 毫秒，HNSW 查询 2.470 毫秒。索引占 499,712 字节，构建耗时 139.517 毫秒。更新 32 条向量的可比样本耗时从 3.826 毫秒增加至 7.857 毫秒。仅 8 条可访问的高选择性场景验证了安全精确回退。另在真实 HTTP embedding 请求等待时验证同租户业务事务仍可写入。上述数据来自一次本地合成样本。

撤回恢复用实库还原旧正文与向量记录后重放撤回。正式模型质量、Langfuse 服务端评分入库、生产容量、下游产物清理和物理备份切换由部署环境验收。
