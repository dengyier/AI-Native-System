## 接入和验收记录，由实施方填写

1. 用约定身份执行一条已获准的只读请求。记录测试环境、对象范围、可达性、接口响应和独立源查证位置。用响应样例核对字段、来源时间和关联 ID。
2. 建立试点配置与规范对象定位，再登记源身份映射和字段权威。依据真实接口的记录版本、流位置和切点选择同步方式。接口适配器将完整对象记录转为 `SourceEvent`，由现有 `FactSync` 接收。源端若返回字段补丁或关系分页，先补读完整详情和关系，再提交该对象记录。以可证实的范围标注覆盖。版本顺序、切点或关系完整性无法证明时，先记录独立只读核对结果，依赖该证据的判定继续待验。
3. 在试点主库登记规则及选定发布，用 [Ontology 权威只读查询](P9-企业试点与恢复演练.md#ontology-权威只读查询) 比对对象、关系、来源、规则版本和人工预期。查询由指定身份发起，结果记录保留样本编号和来源引用。当前接口使用所选发布和主库观测时间，制度交界按 [试点制度切换](P9-企业试点与恢复演练.md#试点制度切换) 的隔离发布演练或实际切换窗口验证。变更规则定义时更新规则版本和 Ontology 版本。
4. 对照通过的样本记录预期与实际。差异记录到源数据、映射、规则、权限或制度版本及负责人。验收需确认未出现跨租户或越权披露、任务创建、模型和工具调用、授权签发及业务源写入。
