# 六层框架与 OpenWorkProof 集成开发计划

P0 至 P8 已在本地验收。P9 已完成本地 Agent 执行隔离、真实 PostgreSQL 多副本主备切换及逻辑恢复，正式企业试点待接入。[六层系统架构与复用方案](../../六层系统架构与复用方案-OpenWorkProof.md) · [深入审查记录](../../六层架构深入审查-2026-11-16.md) · [P0 环境验收](../../P0-环境验收.md) · [P1a 契约验收](../../P1a-契约验收.md) · [P1b 主库验收](../../P1b-主库迁移验收.md) · [P2a 企业治理验收](../../P2a-企业身份权限与发布验收.md) · [P2b 双源事实与规则验收](../../P2b-双源事实同步与规则验收.md) · [P3 授权与执行验收](../../P3-OpenWorkProof授权与执行验收.md) · [P4 工具与证据验收](../../P4-MCP条件写入与证据闭环验收.md) · [P5 模型与观测验收](../../P5-模型接入与观测验收.md) · [P6 编排与恢复验收](../../P6-LangGraph编排与断点恢复验收.md) · [P7 权限知识与评测验收](../../P7-权限知识检索与评测验收.md) · [P8 应用与运行台验收](../../P8-通用应用SDK与运行台验收.md) · [P9 企业试点与恢复演练](../../P9-企业试点与恢复演练.md)

**目标：** 在现有通用框架上接入 OWP 安全核心与成熟组件，使查询、生成、受控写入应用共享可验证的权限、执行、证据与发布机制。

**架构：** 已确定 PostgreSQL 为正式主库，pgvector 为知识向量存储与检索后端。保留本框架的语义、任务和执行治理契约，以适配器接入 OWP、MCP SDK、LiteLLM、LangGraph、LlamaIndex 和 Langfuse。SQLite 留作原有基线与轻量演示，主要开发与集成验收以真实 PostgreSQL 为准。Temporal 和复杂资源授权后端在明确需求后引入。

P0 实施与验证使用公开发布包，外部 OWP 工作树用于源码核对。后续阶段按依赖执行、检查并更新清单。

## 1. 基线与阶段顺序

开发与验证从本项目根目录运行。独立发布以本目录下的框架代码、样例、文档和测试为范围。

深入审查在 Python 3.14.5 上复测 59 项通过并定位 6 条 SQLite 连接告警。P0 修复这 6 处连接关闭后，以同样的资源告警和分配栈诊断重跑，59 项通过、11.254 秒，日志无 `ResourceWarning` 或析构异常。具体复测、依赖和数据库记录见 [P0 环境验收](../../P0-环境验收.md)。

推荐主序列：**P0 PG/pgvector 环境 → P1a Ontology 与通用契约 → P1b PG 主库与迁移 → P2a 身份、语义查询权限与发布 → P2b 事实同步与规则判断 → P3 OWP 语义授权绑定 → P4 工具与证据闭环 → P5 模型、embedding 与追踪 → P6 Agent 编排 / P7 pgvector 权限知识与评测 → P8 应用交付 → P9 企业部署。**

P1a/P1b 是 P1 的前后步骤，P2a/P2b 是 P2 的前后步骤。同步的接收、映射与读取服务先用受限服务身份建设；Agent 对外写入直到 P3/P4 通过才开放。没有本体版本、事实来源及读取集，不能先宣称完成语义授权。

深入审查进一步收紧 P1b：显式迁移、并发状态转换、PG 租约、连接上限/健康状态、单实例备份恢复均为基础交付内容；P9 负责企业多副本/主备切换和指定恢复目标，不是首次验证能否恢复。P2/P3 延续第一层设计并补权限/授权验收，不把六个逻辑层当作彼此完全独立的开发批次。

pgvector 扩展可用性在 P0 验证，正式知识表、向量管线和索引在 P7 建设。P7 同时依赖 P1 的 PostgreSQL、P2 的权限、P3/P4 的授权与证据，以及 P5 的 embedding 模型接口；通过 P5 的阶段链继承这些依赖。P6 和 P7 可以独立开发，P8 汇合验收。数据库基础不再等到 P9 才建设。

**基础设施退出验收：** 同版本并发 upsert 不能覆盖已提交新值；并发回执只记一次效果；提交后断连先查状态；旧租约持有者晚到不能提交。运行账号无法 DDL；连接池耗尽和锁等待在配置期限内结束；不就绪时拒绝新接收而不丢已持久任务。单实例恢复后数量/摘要/待对账状态可核对。对应 D1-02 至 D1-07 的本阶段用例必须通过，未到阶段的 OWP/P9 用例继续保持待验。
