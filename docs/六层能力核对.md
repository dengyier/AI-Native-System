## 按依赖推进

1. **先完成本地契约和回归。** 固定 Registry、数据、模型路由、工具以及任务和审批接口的行为。验证同任务并发推进、流程取消与重启、审批后版本漂移、重复执行、防串租户及故障注入。只把通过验证的行为纳入框架保证。
2. **确定对外服务和可信身份。** 把通用入口连到接入方的 HTTP 或应用服务，定义用户、租户和工具服务身份映射。配好对象权限、秘密管理和可核对的审计，限于测试数据先运行一个只读接入。业务数据、模型凭据和工具凭据使用各自权限边界。
3. **接入一条能对账的写入路径。** 配置一个真实系统测试接口和批准后的动作。工具用稳定操作标识携带获批的目标、参数、版本和执行上下文。远端支持幂等键时复用同一个键，远端可查询时先核对回执。未知状态进入对账或人工复核。MCP 能标准化工具与上下文接入，业务授权和操作确认由动作工具负责。 [MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) · [MCP 授权](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization) · [Temporal 幂等活动说明](https://docs.temporal.io/activity-definition#idempotency)
4. **开展受控试点与模型评估。** 先测模型建议质量、证据准确性和操作拒绝能力，再按批准范围开放写入。记录人工基线、任务完成率、误操作、接管率、耗时和成本。以第二个实际应用衡量需要新增的代码和配置。扩大使用前固定模型、提示、规则和工具版本，建立评测、回退与事件响应。
5. **按负载和共性需求扩展。** 按多租户隔离、SLO 与容灾演练选择多节点运行、任务持久调度和外部数据库。按实际知识规模和检索准确率引入文档与向量能力。跨系统共享语义、查询和推理的需求足以支撑维护成本时再抽取独立 Ontology。多个相对独立的 Agent 分工带来可测的质量或时延收益时，再增加动态编排、隔离和资源限额。 [Foundry 对象、关系与动作实例](https://www.palantir.com/docs/foundry/ontologies/ontologies-overview) · [Anthropic 多 Agent 研究实践](https://www.anthropic.com/research/multi-agent-research-system)

## 运行保证的适用边界

执行租约保存在同一个 SQLite 文件中，未过期租约可抑制同阶段并发模型调用。进程中断后等待租约过期可重新领取；旧领取者的迟到结果会丢弃。租约过期时，供应商侧旧请求可能仍在执行，调用次数预算按运行时开始的阶段请求计数，显式模型回退可能再产生一次供应商调用。取消停止后续接受结果与写入，供应商请求本身可能继续到超时。

工具插件是可信 Python 代码，必须把副作用限制在传入的 SQLite 事务内。当前本地事务工具契约适用于扩展本地动作；远端 HTTP/MCP 使用独立的持久操作记录，在数据库事务之外调用网络，固定操作 ID 与摘要，通过执行回执确认未知结果。远端实际业务修改必须由接入服务完成原子去重，协议见 [远端工具与回执对账](远端工具与回执对账.md)。知识搜索是确定性子串查询，Runtime 按应用声明加载规则 ID。对象按租户和动作角色授权，细粒度对象 ACL 尚待企业身份接入。

模型目录支持名称、版本标签、启用状态、能力标签及显式单跳回退。应用指纹包含阶段模型路由名称和指令。供应商真实模型版本、价格和路由配置的发布锁定仍需模型运营能力。指标记录已完成调用的耗时、已报告 Token 与缺失用量次数，金额成本需价格表与完整供应商计费记录。
