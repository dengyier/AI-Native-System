# 远端工具、MCP 与执行回执对账

框架先把获批动作保存为持久操作，再通过 HTTP 或 MCP 请求远端执行。操作 ID 固定为任务 ID，请求摘要绑定动作、对象版本、租户和执行身份。远端服务必须在自己的事务边界中原子提交去重记录、业务修改和回执。客户端重启后用同一操作查询执行结果。

## 接入与调用

在应用注册文件的动作中指定 tool 与 tool_version，例如 remote.transition / 1。用 [适配配置](../fixtures/remote-tools.example.json) 登记地址、协议和超时。idempotent 为 true 表示接入方已验证远端去重契约。Python 直接 register_remote 的调用者同样负责确认这一契约。受保护服务可增加 token_env 字段，指向保存 Bearer 凭据的环境变量。凭据通过请求头发送，持久操作记录保存地址及工具名称。

~~~bash
python3 -m ai_native_system --db /path/to/state.sqlite   --registry /path/to/applications.json   --tools-config fixtures/remote-tools.example.json advance TASK_ID

python3 -m ai_native_system --db /path/to/state.sqlite   --registry /path/to/applications.json   --tools-config fixtures/remote-tools.example.json reconcile TASK_ID
~~~

inspect 包含 operations、原请求摘要、远端响应、尝试次数及业务回执。work 会处理 reconciling 任务，已发出的操作通过查询对账。HTTP 应用入口支持 POST /v1/tasks/任务ID/reconcile 与 POST /v1/tasks/任务ID/retry-remote，后者继续检查原请求者身份。

## 操作与回执契约

HTTP 适配器分别 POST 到配置地址的 /execute 与 /lookup。MCP 适配器把同一操作对象作为 tools/call 的 arguments，调用配置中的 execute_tool 或 lookup_tool。

请求字段包括 operation_id、request_hash、tenant、action、object_id、expected_version、from_state、to_state、requester、approver 和 executor。request_hash 为其余字段按键排序、UTF-8 JSON 紧凑编码的 SHA-256。远端按操作 ID 找到原请求，再对照摘要和实际内容。远端授权以经过验证的调用凭据及委托关系为依据，身份字段用于关联审核。

成功响应中的操作 ID 和请求摘要必须逐字回传请求值。

~~~json
{
  "operation_id": "OPERATION_ID",
  "request_hash": "REQUEST_HASH",
  "status": "succeeded",
  "result": {"state": "verified", "version": 2}
}
~~~

本版动作仍是类型化对象状态变更。成功回执的 state 必须匹配获批目标状态，version 必须为 expected_version + 1。查询还可返回 pending、not_found 或 rejected，始终回传操作 ID 和摘要。明确拒绝应返回正常协议响应中的 rejected。HTTP 错误、MCP isError 和协议失败进入结果待确认路径，因为通信错误本身无法证明副作用是否发生。

## 状态与恢复

| 情况 | 框架行为 |
| --- | --- |
| 准备完成，尚未发出 | 保存 prepared 操作，可以直接取消。重启后 advance 可发送这笔尚未发出的操作，reconcile 保留准备状态 |
| 发出请求前 | 重查权限、审批、事实与目的地址，持久化 dispatched，再释放事务并调用网络 |
| 完整成功回执 | 校验 ID、摘要、结果，并在本地事务中提交对象投影、回执、审计和任务完成状态 |
| 超时、断连、格式或摘要错误 | 保持 reconciling，记录 unknown 或无效回执事件 |
| 回执查询成功 | 确认远端实际结果，沿用原操作 ID |
| 查询 pending 或 not_found | 保持 reconciling，not_found 也可能意味着旧请求仍在路上 |
| 明确 rejected | 任务进入 failed，保存拒绝回执 |
| 远端成功，本地版本已变化 | 保存真实回执并进入 reconciliation_conflict，保留本地已有数据供人工核对 |

retry-remote 用于查询得到 not_found 后显式重发。它再次查询，验证原请求者、当前权限、审批和事实，然后发送同一个操作 ID 与原请求。远端幂等机制必须保证并发到达的旧请求和重发请求共用同一个结果。HTTP 地址与 MCP 工具名称在提议中绑定，地址变化会阻止向新目的地续发。

已经 dispatched 的请求可能产生业务效果，此后 cancel 记录延后取消并继续对账。需要撤销实际效果时，应定义新的、单独获批的补偿动作。

## MCP 支持范围

实现 MCP 2025-11-25 Streamable HTTP 客户端，包含 initialize、initialized 通知、工具发现和分页、tools/call、JSON 及 SSE 响应解析、会话与版本请求头，以及尽力关闭会话。工具结果支持 structuredContent，或单个含 JSON 的文本块。每次执行或查询创建新会话，服务端应在会话之外持久保存业务回执。 [传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) · [生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) · [工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

本版使用预配置 Bearer 凭据。OAuth 发现与授权、STDIO、旧版 SSE 传输、服务端采样或交互请求、流断点恢复尚待实现。网络错误交给业务回执对账处理。读取上限为 256 KiB，timeout 为每次套接字操作等待时间。适配器可连接提供上述执行及查询工具的 MCP 服务，其他工具需要相应参数映射。

## 实际测试

测试自动启动真实回环 HTTP/MCP 端点和独立的远端 SQLite 数据库，测试结束后关闭服务。

~~~bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_remote*.py' -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_mcp_runtime.py' -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
~~~

覆盖远端提交后断开 TCP、独立 CLI 进程恢复、查询失败、缺失回执、显式重发、取消、并发执行、权限撤回、摘要不匹配和本地投影冲突。MCP 集成测试先完成远端写入，再模拟服务端报错，通过新会话查回成功回执，核实执行工具只被调用一次。测试服务的事务与回执实现见 tests/remote_server.py。

验证使用合成对象和受控失败。接入真实企业服务时，还需核验其实际幂等、权限和回执持久性。

验收结果为全量 59 项通过。HTTP 远端运行测试 14 项、传输测试 6 项、MCP 运行测试 1 项，原有 38 项回归全部通过。
